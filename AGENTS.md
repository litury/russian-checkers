# Правила команды damka

## Рабочий цикл
- Небольшая локальная задача: реализация → минимальная самопроверка → результат пользователю. Не планировать и не делегировать простейшую правку без пользы.
- Не запускать полные tests/build/browser-regression и отдельного QA на каждую правку. Полноценный QA — по явной просьбе пользователя, на стабильном наборе изменений.
- Разработчик отвечает за минимальное подтверждение работоспособности своего изменения: целевой запуск/проверка, просмотр UI или проверка сборки после удаления зависимостей. Проверять пакет изменений, а не каждый patch. Не строить новый harness ради косметики.
- Проверять затронутое: изменение загрузки не требует повторять все взятия/дамки/результаты. Для правил игры, часов, сохранений, безопасности и массового удаления объяснить риск и согласовать расширенную проверку.
- Не выдавать самопроверку за независимый QA. Статусы разделять: реализовано; локально проверено; QA пройден; опубликовано. Непроверенное называть явно.
- Ограничивать повторные попытки; сбой окружения не превращать в бесконечный ремонт проверок. Сразу сообщать о блокере, не ждать вопроса пользователя.

## Роли
- Координатор: конечный объём, критерии, контроль времени и статуса, без самовольного расширения.
- Developer: код и минимальная самопроверка.
- QA: независимые проверки, регресс, устройства и крайние случаи по отдельному запросу; конкретные дефекты без побочного рефакторинга.
- Illustrator: новые изображения по утверждённому направлению; платная генерация только с разрешения.
- DevOps: точный локальный кандидат и Tuna; не подменять его старым туннелем или Pages.

## Сохранность и публикация
- Не трогать чужие dirty worktrees, активные чаты, серверы и туннели. Для параллельной работы использовать изоляцию.
- Удалять только доказанно неиспользуемое: проверять импорты, HTML/CSS URL, preload, glob, динамические ключи. Masters, лицензии и исторические previews сохранять.
- Без отдельного разрешения никаких commit/push/deploy. Просьба о preview не разрешает публикацию. Учитывать, что push main может запустить автоматический deploy.
- Не коммитить docs/handoff-* и docs/preview-*. Автор Git: Litvinov Y. <litury@icloud.com>.
- Перед выдачей Tuna URL сверять публичный HTML/ресурсы с конкретным кандидатом. Называть ссылку временной и публичной, если нет авторизации.

## Утверждённый интерфейс
- Русские шашки; основной заголовок Literata 600, UI Golos Text. Opening slogan (`.opening-slogan`) циклически печатает flavor-фразы (type → hold → erase → next) из одного массива; статичный «Великие планы. Неизбежные жертвы.» не использовать. Нижний `#opening-status` — только ошибки загрузки, без flavor. Убрать только дублирующее верхнее название.
- Opening PNG показывать целиком после load+decode, с зарезервированной геометрией; отказ декора не блокирует игру.
- «Играть» разблокируется из HTML-gate как можно раньше (не ждать Phaser preload); после клика допустим краткий wait, если match-assets ещё грузятся. Reduced motion без анимаций, честные error/retry; помощь и настройки доступны при загрузке.
- Сохранять текущие Reliquary art, HiDPI, маркеры, HUD и игровую механику; не возвращать retired-декор по старым инструкциям.

Эти актуальные договорённости заменяют прежнее требование полного регресса после каждой мелкой итерации. Текущая явная просьба пользователя имеет приоритет. Для подробностей проекта загружать russian-checkers-hud при наличии.
