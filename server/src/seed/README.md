# Изолированные demo-данные

`npm --prefix server run seed` не имеет DATABASE_URL по умолчанию и не запускает миграции. Сначала оператор готовит пустую disposable PostgreSQL существующим `server/sql/migrations/001_init.sql`. Миграционный рефакторинг не входит в этот срез.

Обязательные настройки: NODE_ENV=development, ALLOW_DEV_SEED=I_UNDERSTAND_DISPOSABLE_ONLY, DATABASE_URL с числовым loopback и явным портом без query options, SEED_DATABASE и SEED_ROLE. Имена БД и роли: `damka_seed_dev_[a-z0-9_]{1,40}`. БД принадлежит этой роли; COMMENT на БД и роли равен `damka:disposable-dev-seed:v1`. Роль без superuser/createdb/createrole/replication/bypassrls и членства в других ролях. Эти свойства проверяются SQL после подключения, перед записью. Loopback сам по себе не доказывает безопасность: создание таких обозначений разрешено только на действительно отдельной disposable БД.

SEED_ONLINE_GAMES (default 16), SEED_BOT_GAMES (default 6): канонические десятичные целые 0..100. Ноль ничего не удаляет. Уменьшение количества сохраняет ранее созданные партии; увеличение добавляет стабильные номера. Fixture damka-demo-v2 использует фиксированную базовую дату 2026-01-01 UTC, IDs и отдельный PRNG для каждого mode/index/retry. Результат зависит также от версии общих правил; изменение правил/fixture требует новой версии, иначе конфликт отклоняется.

Demo players не имеют token_hash/auth_identities и не могут войти в приложение. Это fixture статистики, не аккаунты для интерактивного тестирования. Новые guest-аккаунты для браузера создаются отдельно только на disposable API. Генератор останавливается на первом результате общих правил с историей позиций; вычислительный лимит возвращает unfinished, после ограниченных повторов весь seed отказывается от записи.

Один client, одна транзакция, advisory lock сериализует seed. Ledger `damka_dev_seed.objects` фиксирует принадлежность и fingerprint. Повторный запуск восстанавливает отсутствующие owned rows/plies, но отказывается перезаписывать изменённые/непринадлежащие fixture записи. Ошибка откатывает весь запуск. Ledger не является приложенческой миграцией. Пароли/URL/driver errors не печатаются.

## Ранее созданные данные

Этот генератор не изменяет ранее выданные доступы. Старые утилиты отзыва удалены;
удаление их файлов не отзывает токены в существующей БД. Если старые demo-доступы
выдавались на рабочем сервере, их нужно отдельно проверить и безопасно отозвать.
