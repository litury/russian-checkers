Область: правила, легальность через UI, бот, крайние случаи. Дизайн и рефакторинг вне отчёта.
Код не менялся. `npm test` не запускался: в clone нет `node_modules`, зависимости не ставились.

Источники: README, docs/game-design.md, src/rules/*, pickBotMove, gameScene.onSquare / playHuman / playBot.

## Вердикт

Движок в целом совпадает с GDD среза 1: обязательное взятие, бой назад простой, дамка-летун, турецкий удар (фигуру не прыгают дважды, снятие после серии), превращение в середине серии с продолжением дамкой, нелегальный ход через apply = null, победа = нет фигур или нет хода. Бот берёт только legalMoves.

P0 по правилам не нашёл. Есть P1 на неоднозначный клик цепочки и дыры в спеках.

## Баги

### QA-1. Клик по клетке выбирает ход только по последней клетке path (P1)

Где: `gameScene.ts` `onSquare` — `moves.find` с `move.path[move.path.length - 1]`.

Шаги:
1. Позиция, где у одной фигуры две разные серии взятий с одним и тем же финальным полем (разный порядок жертв / разный path, общий конец).
2. Выбрать фигуру, кликнуть финиш.

Ожидание (GDD: «сторона выбирает любое легальное»): можно указать конкретную серию.
Факт: берётся первый ход в порядке обхода доски / DIAGONALS. Второй path недоступен.
Регрессия: нет теста на коллизию финишей; UI-спек на клик отсутствует.

### QA-2. Промежуточная клетка цепочки не завершает ход и сбрасывает выбор (P1)

Где: подсветка назначения = только last path; `uniqueHopLands` / лучи рисуют и промежуточные клетки.

Шаги:
1. Простая бьёт две фигуры: например белая (2,2), чёрные (3,3) и (3,5); единственный ход `path: [(4,4), (2,6)]` (как в rules.spec).
2. Выбрать (2,2).
3. Кликнуть промежуточную (4,4), не финиш (2,6).

Ожидание: либо ход не применяется, выбор фигуры остаётся; либо (если яма выглядит как цель) ход не должен «пропадать».
Факт: `find` не матчится, клетка не `from`, `selected = null`. Серия не сыграна.
Нелегальный тихий ход при этом всё равно не проходит.

### QA-3. Ничья в срезе не существует (P2, не баг относительно GDD)

`winner` возвращает только сторону или null. Троекратное повторение, 15 ходов дамками, согласие — нет.
GDD: победа = нет фигур / нет легального хода. Для среза 1 ок, для «настоящих русских» — дыра продукта, не регрессия правил среза.

### QA-4. Тест «турецкий удар» почти ничего не ловит (P2 покрытие)

`does not jump the same piece twice`: одна жертва на (2,2), проверяют `path.length === 1` и уникальность клеток path.
Не проверяется: вторая жертва «за спиной» после обхода; невозможность прыгнуть ту же шашку во второй раз при живой фигуре на доске до конца серии; дамка не пролетает через уже «сбитую, но не снятую».

## Что проверено по коду (без красного)

Обязательное взятие: `legalMoves` отдаёт только captures, если они есть. apply отвергает тихий при бое. UI ходит только из legalMoves.

Бой назад простой: все DIAGONALS, шаг 2. Спек есть.

Дамка-летун: тихий — луч до блока; бой — пустые до жертвы, посадка на любое пустое за ней. Посадка на клетку жертвы запрещена (`hasMove(..., [2,2])` false).

Турецкий удар в генерации: жертвы не снимаются до конца поиска; `captured` Set; `kingCaptureOptions` на уже сбитой клетке `break` (через неё не лететь). apply снимает все captured после цикла path.

Превращение: в поиске и в apply простая на дамочном ряду становится дамкой и может бить дальше. Спек mid-series есть. Тихое превращение в apply есть, отдельного теста нет.

Нелегальный через UI: чужая / своя без хода / пустая не в legal from; apply после клика. Своя без взятия при обязательном бое — deny, ход не применяется.

Бот: `pickBotMove` = uniform(legalMoves). Нелегальный не выберет, пока legalMoves верен. Спек: старт и один бой.

Тупик: winner при пустом legalMoves. Спек: нет фигур; запертая простая.

Ориентация: visRow = 7 - row, белые визуально снизу. Вперёд белых row+1 согласован с экраном.

Resign только в phase human, победа чёрных. Человек всегда белые.

## Дыры в тестах (приоритет дописывания)

Нет / слабо:
- тихий ход простой только вперёд; тихий дамки на N клеток; блок своей / чужой
- простая не бьёт через две и не садится на занятую
- две смежные вражеские на диагонали дамки — одно взятие, не «через обе»
- ветвление серии (две жертвы в разные стороны), не-максимум (GDD: максимум вне среза — нужен явный тест «короткая серия легальна, если она терминальна»)
- коллизия двух path с одним финишем
- клик / gameScene (хотя бы чистая функция выбора хода)
- тихая коронация
- бот: несколько взятий, не выбирает тихий
- winner не ничья (документировать)

Есть: старт 12+12, mandatory capture, бой назад, летун+посадки, слабый turkish, снятие после серии, коронация в серии, apply reject, winner два случая.
