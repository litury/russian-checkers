# Архитектура — срез 1

Пиксельные русские шашки для Яндекс Игр. Один деплой: Phaser-клиент ZIP в Яндекс. Свой сервер и лендинг в срезе нет.

## Цель среза

В срезе:

1. Движок русских шашек: бой назад, обязательное взятие, дамка летает, турецкий удар
2. Стол: пиксель, подсветка легальных ходов, первый клик без стены правил
3. Партия с ботом: бот ходит легально, если есть взятие — берёт; среди легальных выбирает случайно
4. Game Ready без логина; interstitial только после партии

Вне среза: WSS, комната на двоих, реконнект, hotseat, лендинг, Next, лестница ботов, сложность, рейтинг, скины, чат, туториал, правило максимума взятий, аккаунты, БД.

Онлайн — следующий срез, не этот. Модуль `src/rules` уже сейчас без I/O, чтобы потом импортировать его и сервером, не переписывая.

## Границы

Один процесс в рантайме: браузер Яндекс Игр.

### client

Phaser 3, TypeScript, Vite, Yandex Games SDK. Мы клиент не хостим.

Владеет:

- пиксельная доска, подсветка, ввод
- `ysdk.features.LoadingAPI.ready()` при старте, без логина
- interstitial только после партии
- цикл партии: человек ходит, бот отвечает
- локальный `src/rules` для легальных ходов, применения хода, победы

Не владеет сетью, матчмейкингом, страницей-лендингом.

### bot

Не отдельный сервис. Модуль клиента `modules/bot`. На вход — позиция из `src/rules`, на выход — `from` + `path` (как у человека). Нет поиска в глубину, нет оценочной функции, нет уровней.

Не владеет доской и SDK. Среди нескольких взятий — любое, не самое длинное (максимум вне среза).

### rules

Чистый TypeScript, без DOM, Phaser, SDK, сети. Единственный источник правил. Клиент и (позже) сервер импортируют один модуль.

## Бот

После хода человека:

1. `rules` считает легальные ходы стороны бота
2. если множество взятий непустое — только оно (обязательное взятие)
3. равновероятно выбирается один ход, включая цепочку турецкого удара целиком
4. тот же `apply`, что и у человека

UI: без текста правил. Подсветка легальных — только для человека. Ход бота виден на столе, без отдельного «экрана ИИ».

## Яндекс

- Game Ready один раз на старте, без логина
- interstitial после партии, не перед
- пауза по событиям SDK, если платформа шлёт pause/resume
- ZIP — единственный артефакт поставки

## Стек

- Клиент: Phaser 3, TypeScript, Vite
- Правила: TypeScript, без рантайм-зависимостей
- Деплой: ZIP в Яндекс (CI позже)
- Next / Node-сервер / БД — нет

## Приёмка

Источник: [issue #2](https://github.com/litury/russian-checkers/issues/2), правила стола — [game-design.md](game-design.md). Документ не заменяет тикет, фиксирует то, что режет границы.

- Первая сессия: Game Ready без логина, доска сразу, легальные клетки подсвечены, первый клик ≤15 с, без стены правил.
- Нелегальный ход не применяется. Есть взятие — тихий ход закрыт. Несколько взятий: игрок (и бот) выбирает любое; **правило максимума в срез не входит**.
- Дамка летает и бьёт через пустое поле. Турецкий удар: фигуру не прыгают дважды, снятие после всей серии.
- Бот: один случайный легальный ответ; серия взятий = один ход. Не ищет сильнейший.
- Конец: нет ходов или нет фигур → экран результата → ещё раз. Interstitial только после **первой законченной** партии, не до первого хода. Sticky не перекрывает доску.
- Hit-area = клетка. Клетка и фигура читаются с телефона.
