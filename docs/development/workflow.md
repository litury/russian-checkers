# Работа над игрой

## Команды из корня

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Только браузерный клиент |
| `npm run dev:api` | API с перезапуском после изменений |
| `npm run dev:all` | Клиент и API вместе; Ctrl+C останавливает оба |
| `npm run typecheck` | Типы клиента и сервера |
| `npm run typecheck:watch` | Непрерывная проверка типов обоих приложений |
| `npm run check:boundaries` | Проверка границ импортов клиента, сервера и общего кода |
| `npm run verify` | Границы модулей, типы обоих приложений и production-сборка |
| `npm run check` | Общий Biome; в старом коде остаётся lint-долг |

После `npm ci` и `npm --prefix server ci` скопируйте `.env.example` в `.env.local`
и укажите отдельную локальную БД. `dev:api` и `dev:all` читают окружение Vite
и переменные процесса. API автоматически применяет миграции.
Команды не создают и не запускают PostgreSQL, не освобождают занятые порты.
Для PostgreSQL из [macOS-инструкции](localSetup.md) укажите порт БД `55439`.
Для Docker Compose из корня — `5433`.

Отдельный клиент поддерживает обычный Vite reload/HMR. Изменение кода Phaser
может перезапустить игру; сохранение текущей партии при HMR не обещается.

## Быстрые игровые состояния

В dev-сервере можно открыть:

- `/?dev=match` — сразу партия с ботом.
- `/?dev=king` — позиция с дамками.
- `/?dev=capture` — обязательная серия взятий.
- `/?dev=promotion` — ход на дамочное поле.
- `/?dev=clock` — три секунды до таймаута.
- `/?dev=result` — победа; `&outcome=loss` или `&outcome=draw` — другой итог.

Эти страницы используют настоящие правила, отключают автоход в сценарии и
не отправляют результаты бота в API. Нормальная страница `/` не меняется.
Сценарии загружаются только при `import.meta.env.DEV`; в production их нет.
Они не подменяют серверную авторизацию и не предназначены для онлайн-партий.

## Главное меню

Рабочая страница `/` использует общую композицию телефона и десктопа:
«Играть» открывает выбор бота или онлайна, «Профиль» — личную статистику,
историю партий, настройки, правила и аккаунт. Выбор стороны и общий счёт
онлайн-побед находятся на главном экране. Настройки сохраняются в браузере;
режим бота использует выбранную сложность. Онлайн работает через обычный API.

Заголовок, кнопки и общая панель выбора стороны со счётом собраны в
`client/features/menu/assets/menu-controls/atlas.webp`.
JSON рядом хранит координаты nine-slice, исходники и их SHA-256.
У кнопок есть обычное состояние, наведение, нажатие, фокус и недоступность;
основной и второстепенный варианты имеют одинаковую безопасную область текста.
Нарезка сохраняет углы: при переносе текста растёт середина кнопки.
Атлас WebP сохраняет alpha без потерь; между фрагментами есть отступы
и экструзия краёв. Каменный фон `background.webp` и ресурсы анимации
остаются отдельно. При недоступном атласе HTML-кнопки сохраняют
подписи, фокус и работоспособность.

При первом открытии загрузочный экран скрывает неоформленное меню до
декодирования атласа, фона и загрузки основных шрифтов. API статистики и
игровой движок не блокируют появление меню и загружаются независимо.
Ошибка критической графики открывает доступный HTML-вариант; отдельный
таймаут в HTML снимает экран загрузки через 8 секунд даже при сбое JS-модуля.

Выбор стороны использует общий рендер шашек и огня: Canvas собирает готовые
изображения; общая подложка и её края — растровые спрайты. До загрузки анимации
остаются статичные спрайты; reduced motion сохраняет неподвижный огонь.
Стрелки клавиатуры переключают сторону. Анимация приостанавливается за
диалогами и останавливается на время партии. Возврат работает кнопкой,
Escape и историей браузера. Отдельной страницы прототипа больше нет.

## Проверка изменений

Начните с `npm run verify`. Затем проверьте изменённый сценарий в браузере:
ход/ответ/отмена, серия взятий, превращение, сдача, таймаут, повторная партия.
Для интерфейса проверьте 320×568, 375×667 и desktop, reduced motion и resize.
Онлайн проверяйте только на отдельной локальной БД двумя клиентами;
dev-сценарии не заменяют очередь, handshake и реконнект.

Старый автоматический тестовый набор и разовые отчёты не возвращаются.
