# Работа над игрой

## Команды из корня

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Только браузерный клиент |
| `npm run dev:api` | API с перезапуском после изменений |
| `npm run dev:all` | Клиент и API вместе; Ctrl+C останавливает оба |
| `npm run typecheck` | Типы клиента и сервера |
| `npm run typecheck:watch` | Непрерывная проверка типов обоих приложений |
| `npm run check:boundaries` | Проверка границ импортов клиента, сервера и общего кода |
| `npm run verify` | Границы модулей, типы обоих приложений и production-сборка |
| `npm run check` | Общий Biome; в старом коде остаётся lint-долг |

После `npm ci` и `npm --prefix server ci` скопируйте `.env.example` в `.env.local`
и укажите отдельную локальную БД. `dev:api` и `dev:all` читают окружение Vite
и переменные процесса. API автоматически применяет миграции.
Команды не создают и не запускают PostgreSQL, не освобождают занятые порты.
Для PostgreSQL из [macOS-инструкции](localSetup.md) укажите порт БД `55439`.
Для Docker Compose из корня — `5433`.

Отдельный клиент поддерживает обычный Vite reload/HMR. Изменение кода Phaser
может перезапустить игру; сохранение текущей партии при HMR не обещается.

## Быстрые игровые состояния

В dev-сервере можно открыть:

- `/?dev=match` — сразу партия с ботом.
- `/?dev=king` — позиция с дамками.
- `/?dev=capture` — обязательная серия взятий.
- `/?dev=promotion` — ход на дамочное поле.
- `/?dev=clock` — три секунды до таймаута.
- `/?dev=result` — победа; `&outcome=loss` или `&outcome=draw` — другой итог.

Эти страницы используют настоящие правила, отключают автоход в сценарии и
не отправляют результаты бота в API. Нормальная страница `/` не меняется.
Сценарии загружаются только при `import.meta.env.DEV`; в production их нет.
Они не подменяют серверную авторизацию и не предназначены для онлайн-партий.

## Завершение партии

«Отмена» и «Сдаться» используют текстовые компактные кнопки общего атласа меню,
без мелких декоративных иконок. Размер текста не масштабируется вместе с панелью. Недоступная отмена
остаётся в фокусе клавиатуры; нажатие показывает причину без выполнения действия.
Она возвращает свой ход, ответ компьютера и сохранённые часы, но только после
завершения анимации и ответа бота. Пауза, серия взятий и ожидание результата
блокируют отмену; в онлайн-партии кнопка скрыта.

Подтверждение сдачи открывается без ожидания картинок. Фокус сначала на
«Продолжить игру», часы продолжают идти. Отправленная сдача не отменяется
закрытием окна. Если сервер не подтвердил результат за пять секунд, можно
повторить запрос или вернуться к доске; поздний результат всё равно принимается.
Общие условия действий находятся в `match/actions/matchActionState.ts` и
проверяются как в интерфейсе, так и в обработчиках игры.

Победа, поражение и ничья используют один нативный диалог и общий атлас меню.
Порядок действий одинаков: новая партия или поиск соперника, просмотр доски,
возврат в меню. Высота зависит от текста; при увеличении шрифта прокручивается
содержимое окна, а выход в меню остаётся доступным.

После закрытия результата кнопки «Результат» и «В меню» находятся внутри нижней
панели. Их координаты берутся из `playerPanelLayout` и `matchActionGeometry`,
как у игровых действий. Доска не уменьшается, дополнительная прокрутка страницы
не включается. Escape возвращает к доске и повторно открывает результат.
Старые изображения из `match/result/assets` не загружаются и не входят в сборку.

Обе игровые панели используют `match/hud/playerPanel.ts` и один растровый атлас
`hud/assets/gothic`: панели и часы производны от одобренного арта меню,
информационные углубления нарисованы отдельно в той же семье. Nine-slice сохраняет
углы, а текст и цифры имеют одинаковый масштаб по обеим осям независимо от
пропорций панели. Рамка таймера всегда на месте: активный ход выделяется тёплой
кромкой, последние девять секунд — красноватой, без ламп и раздвижения рамки.
При коротком экране статус переносится под цифры справа, доска не меняет размер.
Появление панелей — плавное проявление в общей подготовке партии, без дверей,
пара и дополнительного ожидания декоративной анимации. Ошибка атласа оставляет
простые читаемые панели и не блокирует игровые действия.

Верхняя панель показывает «Компьютер», выбранную сложность и маркер цвета шашек;
онлайн — «Соперник» и его цвет, без выдуманного имени. В нижней панели отдельная
углублённая область статуса располагается над действиями; компактная версия —
под часами. На узких экранах используются короткие, заранее определённые подписи,
а не уменьшение букв по горизонтали. «Обязательное взятие» и «Продолжите взятие»
отличаются от обычного хода, но не ограничивают выбор маршрута сверх правил движка.

`hud/panelState.ts` задаёт приоритет состояний: подтверждённый итог, ожидание
результата, потеря связи, пауза, подготовка, игровой ход. После партии заголовок
результата использует Literata; причина показывается только если помещается,
иначе доступна в диалоге результата. Оба таймера приглушены и не получают
активное оформление. Сетевое уведомление больше не может затереть принятый итог.
Невидимая DOM-область объявляет изменения состояния для скринридера; отсчёт
ожидания соперника не вызывает новое объявление каждую секунду.

Типографика всех экранов задаётся ролями в `client/fonts/typography.css`.
Phaser получает те же вычисленные роли через `client/fonts/typography.ts`.
Подписи в углублениях имеют обычную насыщенность 400 и свободные внутренние
отступы. Нижняя строка результата появляется только при наличии места для
обеих строк, межстрочного интервала и вертикальных отступов; иначе причина
остаётся в окне результата и объявлении состояния. Фильтрация меняется только
у текстовых текстур, не у доски и шашек.

## Главное меню

Рабочая страница `/` использует общую композицию телефона и десктопа:
«Играть» открывает «С компьютером / С человеком», «Профиль» — личную статистику,
историю партий, настройки, правила и аккаунт. Выбор стороны и общий счёт
онлайн-побед находятся на главном экране. Настройки сохраняются в браузере;
режим бота использует выбранную сложность. Онлайн работает через обычный API.

Все шаги запуска партии находятся в одной компактной каменной панели.
«С компьютером» показывает три переключателя сложности и отдельный запуск;
последний уровень сохраняется. В общих настройках второго выбора сложности нет.
«С человеком» содержит поиск случайного соперника и ветку «С другом» с созданием
приглашения или вводом кода. Счётчик «Игроков на сайте» виден только в этой ветке:
он включает самого посетителя и не означает размер очереди. Неизвестное значение
отличается от подтверждённого нуля. Сторону в онлайн-партии назначает сервер.

Код копируется только по явному нажатию. На поддерживаемых устройствах доступна
отправка ссылки; параметр приглашения удаляется из URL после начала подключения.
Пустой или неполный код не отправляется; формат и отсутствие приглашения имеют
разные сообщения. При долгом поиске остаётся отмена, таймер продолжает считать
общее ожидание; переход к компьютеру сначала открывает настройку партии.
Возврат кнопкой, Escape или историей браузера отменяет активный поиск/приглашение.
Исторический экран поиска не запускает новую очередь при переходе вперёд.

Заголовок, кнопки и общая панель выбора стороны со счётом собраны в
`client/features/menu/assets/menu-controls/atlas.webp`.
JSON рядом хранит координаты nine-slice, исходники и их SHA-256.
У кнопок есть обычное состояние, наведение, нажатие, фокус и недоступность;
основной и второстепенный варианты имеют одинаковую безопасную область текста.
Компактные переключатели сложности используют отдельные спрайты в том же атласе:
форма собрана nine-slice, выбранный уровень выделен тёплым оформлением.
Нарезка сохраняет углы: при переносе текста растёт середина кнопки.

Профиль и его разделы используют одну панель и общий атлас меню. Заголовок и
кнопка «Назад» остаются на месте, прокручивается только содержимое. История
браузера восстанавливает разделы и просмотр записи, в том числе после обновления.
Корневой профиль показывает число партий и побед без технического ID.
Настройки применяются сразу; при ошибке localStorage показывается предупреждение.
Вибрация недоступна в браузерах без соответствующего API.

Аккаунт пока гостевой: история хранится на сервере, ключ доступа — в браузере.
Вход, перенос профиля и восстановление по почте не реализованы. Незавершённые
email endpoints отвечают 503 `email_unavailable`, не генерируют и не логируют коды.
Существующие игроки, привязки и записи в базе не удаляются.
Атлас WebP сохраняет alpha без потерь; между фрагментами есть отступы
и экструзия краёв. Каменный фон `background.webp` и ресурсы анимации
остаются отдельно. При недоступном атласе HTML-кнопки сохраняют
подписи, фокус и работоспособность.

При первом открытии загрузочный экран скрывает неоформленное меню до
декодирования атласа, фона и загрузки основных шрифтов. API статистики и
игровой движок не блокируют появление меню и загружаются независимо.
Ошибка критической графики открывает доступный HTML-вариант; отдельный
таймаут в HTML снимает экран загрузки через 8 секунд даже при сбое JS-модуля.

Выбор стороны использует общий рендер шашек и огня: Canvas собирает готовые
изображения; общая подложка и её края — растровые спрайты. До загрузки анимации
остаются статичные спрайты; reduced motion сохраняет неподвижный огонь.
Стрелки клавиатуры переключают сторону. Анимация приостанавливается за
диалогами и останавливается на время партии. Возврат работает кнопкой,
Escape и историей браузера. Отдельной страницы прототипа больше нет.

## Проверка изменений

Начните с `npm run verify`. Затем проверьте изменённый сценарий в браузере:
ход/ответ/отмена, серия взятий, превращение, сдача, таймаут, повторная партия.
Для интерфейса проверьте 320×568, 375×667 и desktop, reduced motion и resize.
Онлайн проверяйте только на отдельной локальной БД двумя клиентами;
dev-сценарии не заменяют очередь, handshake и реконнект.

Старый автоматический тестовый набор и разовые отчёты не возвращаются.
