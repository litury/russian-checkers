# Прокси production

## Схема

Игра работает на `puppetgram-ru` (`77.233.223.97`), Dokploy `0.30.7` — на
`puppetgram-de`. Управление приложениями остаётся в Dokploy.

```text
Клиент → TCP 80/443 host → Traefik → damka-edge → API
                                             API → dokploy-network → PostgreSQL
```

Общий сервис `traefik` имеет одну реплику, закреплён на RU и обновляется
в режиме `stop-first`. Существующие TCP 80/443 опубликованы в режиме `host`,
без routing mesh, который скрывал внешний IP. UDP-порты не добавлялись.
DNS, сертификаты, база данных и приложения DE не менялись.

`damka-edge` — отдельная overlay-сеть `10.210.0.0/28`, не attachable.
В ней разрешены только Traefik и API; служебный endpoint Docker не является
дополнительным приложением. Не подключать к ней другие сервисы: принадлежность
к этой сети определяет доверие к `X-Forwarded-For`.

API использует `dnsrr` и сетевой alias `damka-api-edge`, поэтому прокси
обращается прямо к задаче API без общего VIP/SNAT. Адреса задач могут меняться.
`TRUSTED_PROXY_CIDRS=10.210.0.0/28`; общая сеть `dokploy-network` не доверенная.
Порт API наружу не опубликован. Доступ к Docker/хосту остаётся административной
границей безопасности, а не защищается этим списком CIDR.

## Где сохраняются настройки

В Dokploy у `damka-api` (`IBBOvdggGapj1iccmMERw`):

```json
{
  "networkSwarm": [
    { "Target": "dokploy-network" },
    { "Target": "damka-edge", "Aliases": ["damka-api-edge"] }
  ],
  "endpointSpecSwarm": { "Mode": "dnsrr" }
}
```

Переменная доверия хранится в окружении этого приложения. Остальные переменные,
одна реплика, `stop-first` и grace period 20 секунд сохранены.

На RU:

- `/etc/dokploy/traefik/traefik.yml` — существующая статическая конфигурация.
- `/etc/dokploy/traefik/managed-service.json` — сохранённая целевая спецификация
  существующего Swarm-сервиса `traefik`, включая обе сети и host-порты.
- `/etc/dokploy/traefik/dynamic/damka-edge.yml` — отдельный маршрут
  `api.damka.fun` и прежнего API sslip-домена к `damka-api-edge:8787`.
  Приоритет 100 выше сгенерированных маршрутов Dokploy. HTTP перенаправляется
  на HTTPS, TLS использует прежний resolver. Этот файл не является файлом
  приложения, который Dokploy генерирует при изменении доменов.
- `/root/damka-proxy-migrate.py` — инструмент применения и отката конфигурации.
- `/root/damka-proxy-migration/` — закрытые резервные копии исходных service
  specs, настроек приложения и файлов Traefik. Содержат секреты: не публиковать.

Не нажимать переинициализацию Traefik или `server.setup` для RU: штатный код
этой версии ожидает имя `dokploy-traefik`, а действующий сервис — `traefik`.
Он не сохраняет нашу дополнительную сеть автоматически. Обычные перезапуски
задач Swarm сохраняют service spec; обычный деплой API использует настройки Dokploy.
При смене домена, middleware или правил доступа API менять также `damka-edge.yml`:
приоритетный маршрут не наследует будущие изменения маршрута из панели.

Повторное применение сохранённой спецификации общего прокси:

```sh
ssh root@77.233.223.97 'python3 /root/damka-proxy-migrate.py restore-proxy'
```

Это административная операция, не команда для обычного деплоя игры. Перед ней
проверить отсутствие партий и деплоев, согласовать короткий перерыв всех сайтов
на RU. При обновлении версии Traefik обновить и сохранённую спецификацию;
не применять старый снимок поверх намеренно изменённых настроек. При пересоздании
сети её ID изменится: сначала актуализировать ссылки в спецификации.

## Проверки

Изолированный локальный Swarm проверяет маршрут через выделенную сеть,
удаление поддельного внешнего `X-Forwarded-For`, недоверие соседу из общей сети
и работу после смены задач API и Traefik.

На production контрольные GET `/health` из двух внешних источников подтвердили
разные внешние IP в `X-Forwarded-For` и TCP peer Traefik из `damka-edge`.
Подставленный адрес `192.0.2.123` не проходит. Проверены HTTPS, HTTP→HTTPS,
WebSocket upgrade и корректное закрытие без создания тестовых игроков/партий.

Контрольный redeploy через Dokploy завершился успешно: обе сети, alias,
`dnsrr`, переменная окружения и выделенный маршрут сохранились; `/health`
и WebSocket проверены повторно. Автоматический деплой возвращён в исходный
включённый режим, временные таймеры аварийного отката остановлены.

Перед переключением были ответы 502 у `workwolk.ru`, `api.workwolk.ru` и
`mindassistai.ru`; остальные проверенные сайты сохранили прежние ответы.
Это исходное состояние чужих приложений, не результат этой миграции.

## Откат

При недоступности ранее работавших сайтов или неверной передаче IP не продолжать
изменения. Не совмещать откат с автоматическим или ручным деплоем приложения.

1. Временно отключить автоматический деплой API в Dokploy.
2. На RU выполнить `python3 /root/damka-proxy-migrate.py rollback`.
   Команда убирает только добавленный маршрут и восстанавливает исходные
   спецификации API и Traefik. Сеть и резервные копии не удаляются.
3. В Dokploy восстановить исходные `networkSwarm`, `endpointSpecSwarm`, окружение
   и `autoDeploy` из защищённого `application-before.json`. Иначе следующий
   деплой снова применит новые настройки. Изначально оба Swarm override были
   `null`, переменная `TRUSTED_PROXY_CIDRS` отсутствовала, `autoDeploy=true`.
4. Проверить `/health`, WebSocket и сайты на RU. Возвращение к ingress снова
   скрывает реальные IP: это аварийный откат, а не правильный конечный режим.

Изменение инфраструктуры не публикует локальные коммиты. Выпуск нового
парсера доверенных IP и лимитов приложения выполняется отдельно через Git.
