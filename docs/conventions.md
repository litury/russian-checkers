# Соглашения

Применяем идеи исходных референсов к Phaser/Node, без копирования Vue- и C#-структуры.

- Код располагается у доменного владельца, на самом низком необходимом уровне.
- Внутренние детали — в `parts` своего модуля, не в общей папке для всего проекта.
- Ориентир — 7–10 ручных файлов в папке; кадры и другие связанные ресурсы могут составлять больший набор.
- Файлы, переменные и функции TypeScript — `camelCase`; типы и интерфейсы — `PascalCase`.
- Константы уровня модуля — `UPPER_CASE`, новые входные параметры — `_camelCase`.
- Асинхронные прикладные функции используют `async/await` и суффикс `Async`.
- Объектные контракты предпочтительно описывать интерфейсами; не добавлять `any` без причины.
- Публичный `index.ts` только реэкспортирует API модуля. Не создавать его в папках ресурсов ради формальности.
- Комментарии краткие, на русском и объясняют причину решения.
- Не переименовывать старые API массово только ради стиля; внешние контракты сохранять.
- Правила игры независимы от UI, сети и БД. SQL принадлежит серверному домену.
- При переносе проверять импорты, CSS URL, glob, сборку, Docker и происхождение ресурсов.
- Не удалять оригиналы, лицензии и provenance под видом очистки кэша.
- Структурную уборку не смешивать с редизайном и изменением правил.
- Любые новые и изменяемые арты следуют [художественному направлению](art-direction.md); смену стиля согласовывать отдельно.

Проверки после изменений: `npm run build`, `npm --prefix server run typecheck`
и ручные сценарии игры на телефоне и ПК. Общий lint исправляется отдельно;
правила ради успешного отчёта не отключаются.

Сообщения коммитов: `type(scope): действие`, короткий заголовок и причины в теле.
